# Tech stack and commands

## Firmware (`firmware/`)

- Board: STM32F103C8T6 "Blue Pill" (72 MHz Cortex-M3, 20 KB RAM, 64 KB flash).
- Toolchain: STM32CubeMX to configure pins and clocks, STM32CubeIDE to build and flash, ST-Link V2 over SWD.
- Library: STM32 HAL (STM32Cube FW_F1) and the CubeMX USB Device middleware (HID class).
- Language: C99.
- The project is generated by CubeMX. Hand-written code lives only inside `/* USER CODE BEGIN ... */` blocks or in our own files under `firmware/Core/Src/ditdah/` and `firmware/Core/Inc/ditdah/`, so regenerating never erases it.

## Decoder (`decoder/`)

- TypeScript version in `decoder/src/`, published to the Studio as a local package.
- C version in `decoder/c/` (`morse_decoder.c` and `morse_decoder.h`), plain C99 with no HAL, copied into the firmware build.
- Tests: Vitest for unit tests and fast-check for property-based tests (TypeScript); a small C test runner compiled with gcc on a laptop.
- Shared test cases: `spec/morse-vectors.json`, generated by `spec/gen-vectors.mjs`, which also writes `spec/morse_vectors.h` for the C tests. Never edit those two files by hand.

## Studio (`studio/`)

- Next.js (App Router) with TypeScript and Tailwind CSS, deployed on Vercel.
- AI suggestions come from an OpenAI-compatible chat API (Nebius Token Factory), called only from a server route. The key lives in the environment variable `AI_API_KEY`; the base URL in `AI_BASE_URL`; the model in `AI_MODEL`.
- Speech uses the browser's built-in `speechSynthesis`.

## Commands

| Task | Command |
|---|---|
| Regenerate test vectors | `node spec/gen-vectors.mjs` |
| Decoder tests (TypeScript) | `cd decoder && npm test` |
| Decoder tests (C) | `cd decoder/c && make test` |
| Studio dev server | `cd studio && npm run dev` |
| Studio checks | `cd studio && npm run lint && npm run build` |

## Rules for all code

- Never commit secrets. Keys go in `.env.local` (Studio) or Vercel's environment settings.
- Prefer small pure functions that can be unit tested.
- Every new behavior gets a test before it is called done.
- Keep the TypeScript and C decoders behaviorally identical: a change to one is a change to both, plus the shared vectors.
