# Repository structure

```
.kiro/
  steering/        product, tech, embedded and structure rules (this folder)
  specs/
    decoder/       requirements, design and tasks for the Morse decoder
    firmware/      requirements, design and tasks for the Blue Pill firmware
    studio/        requirements, design and tasks for the web Studio
  hooks/           agent hooks created in Kiro (see docs/kiro-hooks.md)
spec/
  gen-vectors.mjs  generates the shared decoder test cases
  morse-vectors.json
  morse_vectors.h
decoder/
  src/             TypeScript decoder
  test/            Vitest unit and property tests
  c/               C decoder and its laptop test runner
firmware/          STM32CubeIDE project generated by CubeMX
  Core/Src/ditdah/ our firmware modules
  Core/Inc/ditdah/
studio/            Next.js web app
hardware/          wiring notes, photos, case files
docs/              setup guides, Kiro notes, screenshots
```

## Naming

- TypeScript: `camelCase` for functions and variables, `PascalCase` for types and classes, files in `kebab-case.ts`.
- C: `snake_case`, with a module prefix (`md_` for the Morse decoder, `dd_` for DitDah firmware modules).
- Commit messages: short imperative sentence, such as "Add sip and puff thresholds".

## Where things go

- A rule that both decoders follow goes in `.kiro/specs/decoder/design.md` and becomes a test vector.
- A hardware fact (a pin, a part, a measurement) goes in `docs/wiring.md`.
- Anything Kiro helped with that is worth telling the judges goes in `docs/kiro-moments/`.
