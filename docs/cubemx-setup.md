# Firmware project setup (STM32CubeMX)

The firmware project in `firmware/` is generated by STM32CubeMX from `firmware/firmware.ioc` for the STM32F103C8 Blue Pill. It is already generated and builds; you only need this page to rebuild, flash, or change a pin.

- STM32CubeMX 6.18.1, STM32Cube FW_F1 V1.8.7
- Toolchain: **CMake** (Ninja + GNU Arm GCC). These ship inside STM32CubeIDE 2.x, so nothing else needs installing.
- Why not the "STM32CubeIDE" toolchain: with CubeMX 6.18 and CubeIDE 2.x, generating for STM32CubeIDE left out the IDE project file, the startup file and the linker script. The CMake output has all three and builds from the command line.

You need STM32CubeIDE 2.x (for its bundled tools and ST-Link support), STM32CubeMX (only to change the configuration), the ST-Link driver (STSW-LINK009) and the CP210x driver.

## Build and flash

From PowerShell in `firmware/`:

```powershell
.\build.ps1          # -> build\Debug\firmware.elf
.\flash.ps1          # writes it to the Blue Pill through the ST-Link and resets it
```

If the scripts can't find CubeIDE, set `STM32CUBEIDE_DIR` to the folder that contains `plugins`, for example `C:\ST\STM32CubeIDE_2.2.0\STM32CubeIDE`.

## Changing the configuration

1. Open `firmware/firmware.ioc` in STM32CubeMX.
2. Change what you need. Keep **Project Manager → Toolchain / IDE** on **CMake**.
3. Click **GENERATE CODE**.
4. Run `.\tools\patch-hid-keyboard.ps1`. CubeMX rewrites the USB HID class as a mouse every time it generates; this turns it back into a keyboard. `build.ps1` stops with a reminder if you forget.
5. Run `.\build.ps1`.

Our code goes only inside `/* USER CODE BEGIN ... */` blocks or in `Core/Src/ditdah/` and `Core/Inc/ditdah/`, so regenerating never overwrites it.

## What the .ioc sets up

### Clock

HSE 8 MHz crystal → PLL ×9 → **SYSCLK 72 MHz**. APB1 /2 (36 MHz), APB2 /1 (72 MHz), USB /1.5 (**48 MHz**), ADC /6 (12 MHz).

### Peripherals

| Peripheral | Setting |
|---|---|
| SYS | Debug: **Serial Wire** (keeps the ST-Link working after a flash); timebase SysTick |
| I2C1 | Standard mode, 100 kHz, PB6 SCL / PB7 SDA (OLED 0x3C, MPRLS 0x18) |
| USART1 | 115200 8N1, PA9 TX / PA10 RX (debug log through the CP2102) |
| USB | Device (FS), PA11 / PA12 |
| USB_DEVICE | HID class, product string `DitDah Keyboard` |
| TIM1 | CH1 PWM on PA8, prescaler 71, period 1666, pulse 833 (600 Hz, 50%) for the buzzer |

### GPIO labels

The firmware uses these names from `main.h` (`BTN_BIG_Pin`, `MOTOR_Pin` and so on). Don't rename them.

| Pin | Mode | Label | What it is |
|---|---|---|---|
| PA0 | Input, pull-up | `BTN_BIG` | Jack 1: big button or any switch |
| PA1 | Input, pull-up | `JACK_DIT` | Jack 2: external dit switch |
| PA2 | Input, pull-up | `JACK_DAH` | Jack 3: external dah switch |
| PB12 | Input, pull-up | `BTN_DIT` | 30mm dit button |
| PB13 | Input, pull-up | `BTN_DAH` | 30mm dah button |
| PB14 | Input, pull-up | `BTN_MODE` | 30mm mode button |
| PB0 | Output, starts low | `MOTOR` | Vibration motor transistor |
| PC13 | Output, starts high | `LED` | On-board LED (lights when low) |
| PA8 | TIM1_CH1 | `BUZZER` | Passive buzzer |

## Wiring the ST-Link

Wire the ST-Link to the 4-pin header at the end of the Blue Pill. Don't plug the Blue Pill's own USB in while the ST-Link's 3.3V wire is connected.

| ST-Link pin | Blue Pill pin |
|---|---|
| SWDIO | DIO (or IO) |
| SWCLK | DCLK (or CLK) |
| GND | GND |
| 3.3V | 3.3 (or 3V3) |

Both yellow jumpers on the Blue Pill stay on **0**.

## If something goes wrong

| Message or symptom | What to do |
|---|---|
| No ST-LINK detected | Install STSW-LINK009, try another USB port, replug the ST-Link |
| Can't connect to the target | Check the four wires. Hold the Blue Pill's RESET button, start `.\flash.ps1`, let go after a second |
| "Could not verify ST device" / unknown device ID | The chip may be a clone (common on Blue Pills). Tell the group; there is a workaround |
| Build fails after regenerating | Check the toolchain in Project Manager is still CMake, then generate again |
